# v0.4 搜索、备份恢复与真实 AI 验证

## 使用

首页右上角的搜索按钮可检索全部月份的备注或分类名。展开筛选后可组合收支类型、分类、起止日期和金额上下限，边界包含当天和对应金额。已停用分类仍可检索，已删除记录不显示。结果按日期倒序，显示笔数和收支合计；点开修改后回到原搜索，条件保留。

设置中的“导出完整备份”保存 JSON 文件；“从备份恢复”通过系统文件选择器读取，校验后显示分类数、有效记录数、已删除记录数与导出时间。返回可取消，只有点击“替换账本并恢复”才写入。恢复采用整本替换，不做合并或重复匹配。

每次替换前先在 App 私有目录原子保存当前账本。设置中的“导出恢复前备份”可将它保存到你选择的位置，需要回退时再导入该文件。私有目录只保留最近一份恢复前副本，请及时导出；卸载或清除应用数据也会删除这份副本。

备份包含全部分类、记录、ID、时间及软删除状态，不包含 API Key 或未确认 AI 草稿。恢复不改变本机 Key，完成后清除未确认草稿和搜索条件。沿用数据库 schema 2，不需要删除或重建用户数据库。

## 校验和事务

支持本 App formatVersion 1、databaseVersion 1 / 2、人民币 CNY 备份，最多 16 MiB、2000 个分类、50000 笔记录。校验 UTF-8、完整 JSON、版本、类型、ID 唯一性、分类关联、收支匹配、金额、有效日期、备注长度和每种收支的兜底分类。已删除记录恢复后保持删除状态。

预览前不写账本。确认时再校验一次结构，恢复前副本保存成功后，在同一个 Room 事务内替换记录、分类和 AI 批次凭据；任何数据库写入失败均回滚。UI 同时清除旧删除撤销提示，防止撤销操作错误引用恢复后的同号记录。

## 自动化验证

`scripts/test-emulator.ps1` 自动启动项目 API 31 模拟器，构建 Debug APK 和测试 APK，运行 JVM 单元测试、lint，覆盖安装并执行设备测试。测试使用独立数据库，不写正式账本。覆盖以下新增场景：

- 跨月份、已停用分类、组合筛选、搜索编辑后返回及条件恢复。
- 无效日期、金额范围、空结果及深色主题大字体显示。
- 备份往返、旧版格式、无效分类关联、重复 ID、非法金额、编码和大小限制。
- 恢复前副本保存失败时不写账本；删除完成后插入故意失败，整个事务仍回滚。
- 保留记录 ID、停用分类及软删除状态，恢复后新增记录正常生成 ID。
- 预览、取消、非法文件、确认恢复、Key 保留、旧草稿清除及恢复前副本导出。

## 真实 AI 测试

2026-10-15 在用户连接的华为 Pura 70 Pro 上，使用 App 内已加密保存的 Key，直接调用生产代码中的 `Qwen/Qwen3.5-4B` 接口，`enable_thinking: false`。测试使用固定合成分类和文字，不读取正式账本，也不保存任何测试记录。Key 未输出到电脑日志。

首轮真实返回遗漏店名，随后加强提示词，要求在 120 字内保留已明确提供的店名、菜品、交通工具及目的地。修正后同一测试完整通过，三组请求分别为：

| 输入场景 | 实际通过的结果 | 本次耗时 |
| --- | --- | --- |
| 老街面馆牛肉面 28 元、地铁去公司 6 元 | 两笔支出；备注“午餐：老街面馆牛肉面”“地铁去公司” | 3.3 秒 |
| 昨天十月工资 8000 元、今天公交车去图书馆 2 元 | 收入和支出分开，昨天日期正确；备注“十月工资”“公交车去图书馆” | 32.1 秒 |
| 金额不清楚的午饭，以及明天计划买的咖啡 | 返回无明确账目，没有虚构记录 | 18.5 秒 |

这验证了当前 Key 的鉴权、模型可调用性及这些案例的提取结果；耗时为该次实测，不能代表稳定延迟或普遍准确率。仍需在草稿页核对结果。

真实测试入口为 `scripts/test-ai-phone.ps1 -AllowPaidRequests`。脚本自动覆盖安装并保留数据，最多三组请求，不自动重试；普通回归在读取 Key 之前就跳过此项，避免无意消耗账户额度。真实接口日志保留在被 Git 忽略的 `.tools/test-results/live-ai-20261015-145326/`，显示 `OK (1 test)`，该测试包含上述三组断言。
