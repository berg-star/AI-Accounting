# v0.7.1 免费模型与费用识别修复

## 问题与改动

原模型 `Qwen/Qwen3.5-4B` 在隔离测试中连极短、无日期的请求也返回 HTTP 503、平台错误码 50508，服务端说明系统繁忙。错误发生在客户端解析账目响应之前，且不需要“昨天”这个词即可复现。

本版使用硅基流动的 `Qwen/Qwen3-8B`。2026-10-25 从[官方价格页](https://www.siliconflow.cn/pricing)再次核实，其输入和输出计价均为零；使用现有个人 API Key，不引入新的服务商。请求继续设置 `enable_thinking=false`、`stream=false` 和 JSON 输出模式。不配置付费备用模型或自动重试；免费模型的价格、额度和可用性以供应商当时的规则为准。

明确已支付或缴纳、用途和金额清楚的费用应识别为支出。用途少见、没有专门分类时使用支出的兜底分类，不因缺少细分类跳过。规则覆盖会费、学费、物业费等费用，而非在本地匹配“团费”后直接生成账目。计划、假设、没有消费用途的转账、借还款和退款继续排除。

所有模型结果仍须经过金额、日期、类型和分类校验，进入草稿后由用户确认才入账。模型选择统一应用于记账、查账、AI 复核、消费对比和月报；数据库结构及本机 Key 存储方式不变。

本次范围按用户要求限定为当天和历史已发生的消费，不开发预支或未来计划记账。对复杂自然语言不作全覆盖承诺，识别结果仍需核对后确认。

筛选中曾出现“已发生支出与未来计划放在同一句”时将计划误提取的情况，该混合场景不属于本次支持范围。请拆开输入并核对草稿，只提交已经发生的事项。

既有 AI 功能也做了兼容调整：查询格式示例按整月或同期要求提供；语义复核按查询类型提供相关规则，并优先判断实际消费用途；月报最小示例引用本次真实结论编号。这样避免查询条件被空数组示例覆盖、地点关键词误当消费用途，以及月报照抄不存在的示例编号。本地金额计算、查询条件校验和月报依据校验继续生效。

## 验证方式

离线单元测试验证金额、跨年日期、团费备注和未知分类回退等协议行为；模拟响应不能证明真实模型已理解原句。

真实记账验收包含十次合成请求：原句“昨天交了3.5元团费”、无日期团费、其他会费、明确历史日期、两天的已发生混合账目，以及计划、假设、转账、退款、借款的排除。还应分别运行现有查账、消费对比和月报真实验收，防止统一换模型影响已有能力。所有请求只使用合成数据，不读取设备账本或写入数据库。

```powershell
# 显式允许真实请求。当前模型免费；未来模型定价可能变化。
# -AllowPaidRequests 保留为兼容的参数名称。
.\scripts\test-ai-local.ps1 -AllowLiveRequests -TextAccounting -Offline
.\scripts\test-ai-local.ps1 -AllowLiveRequests -Offline
.\scripts\test-ai-local.ps1 -AllowLiveRequests -Comparison -Offline
.\scripts\test-ai-local.ps1 -AllowLiveRequests -MonthlyReport -Offline

# 此处的 --offline 仅控制 Gradle 依赖解析，不会关闭真实测试的 API 网络请求。
.\scripts\build.ps1 :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --offline
```

构建产物为 `app/build/outputs/apk/debug/app-debug.apk`，版本号 0.7.1，versionCode 为 8。未经真实验收通过，不应将候选包作为已验证更新交付。真机安装和实际使用结果须单独记录，不能用电脑测试代替。
