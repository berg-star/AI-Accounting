# 下一版设计方案：日常记账与分类管理

状态：设计已确认，v0.2 功能已实现；构建与实际测试结果见 [本版验证记录](verification-v0.2.md)。v0.3 AI 功能仍为后续规划。

日期：2026-10-14。基于当前已能构建、安装和运行的 Kotlin + Compose 项目。

## 1. 咔皮记账的参考点与证据边界

已查看咔皮记账的官方商店展示截图、官网展示，并核对公开版本记录。

- 官方展示以浅色界面、蓝色强调色、圆角卡片、小图标和少量角色插画组织信息。金额比说明文字醒目，概览和记录分区。
- 官网首页展示月度收支概览、按日期组织的记录，以及靠近底部的一句话输入入口。可参考其信息层次与方便触达的录入方式。
- 官方商店的历史版本记录明确写到：预设分类支持删除、改名、修改图标。这说明分类应当能适应个人习惯。
- 尚未核实最新版 Android 分类管理页的完整布局、所有菜单及交互细节。下文的分类规则和页面是本项目自己的提案，不把未确认的二级分类、拖拽排序或合并行为归为咔皮已有功能。

## 2. 下一版范围

建议下一版标为 **v0.2：可以日常使用的本地手动记账版本**。先完成分类、记录和统计的一致性，后续 AI 草稿直接复用这套编辑与保存流程。

| 本版交付 | 内容 |
| --- | --- |
| 明细首页 | 切换月份；本月支出、收入、净收支；按日期分组的记录 |
| 记一笔 / 编辑记录 | 支出或收入、金额、分类、日期、可选备注；修改与删除 |
| 分类管理 | 新增、改名、选图标与颜色、调整顺序、停用 / 恢复、删除未使用分类 |
| 简单统计 | 本月收入 / 支出分类排行、金额及占比；点击查看该分类记录 |
| 本机数据 | Room 持久化；重新打开 App 后数据仍保留 |
| 数据备份 | 设置页提供完整 JSON 备份导出，包含记录与分类 |

单账本、单币种人民币。AI 文字解析作为下一小版 v0.3。语音、截图识别、无障碍自动记账、多账户、多账本、预算、资产、云同步、共享账本、角色养成及复杂报表放到后续需求中，不在 v0.2 展示不可用的占位入口。

## 3. 页面与视觉

底部保留 **明细 / 统计 / 设置** 三个入口；“记一笔”为显眼的主操作，主页与统计页均方便触达。分类管理同时可从设置页和记账页的“管理分类”进入。

### 明细首页

顶部是当前月份和切换按钮，下方是一张月度概览卡。以支出为主要数字，收入与净收支为辅助信息。净收支只表示当月收入减当月支出，不作为银行余额或总资产展示。

记录按日期分组，每行显示分类图标、分类名称、备注及金额；支出带减号，收入带加号，颜色仅辅助区分。点击记录进入编辑页。当天分组标题可显示当天收支合计。

第一次打开没有账目时显示“还没有记录，记下第一笔吧”，概览为真实的零值。正式 APK 不放演示账目。

### 记一笔 / 编辑记录

布局顺序：支出 / 收入切换 → 大号金额输入 → 分类图标网格 → 日期、备注 → 保存。

默认支出、今天；金额初始为空。选中分类应有颜色和勾选两种反馈。优先使用系统数字键盘，做好键盘与导航栏避让，本版不先开发计算器键盘。

只必填金额与分类。金额必须大于零、最多两位小数。备注可为空。保存中禁用重复提交；失败保留输入并说明原因。保存成功返回明细，并立即更新汇总和统计。

从记账页进入分类管理时保留金额、日期和备注，返回后仍继续当前草稿。切换支出 / 收入后只允许选择对应类型的分类。

### 分类管理

顶部切换“支出 / 收入”，右上角新增分类。管理页使用清楚的列表；录入页使用便于点选的网格。

每项显示图标、名称和编辑入口。编辑面板提供名称、有限的图标库和少量低饱和配色。排序模式用上移 / 下移按钮，本版先让功能明确可靠；拖拽排序可以后续补充。

“已停用分类”单独展开，提供恢复操作。管理分类时能看见使用记录数量，帮助判断删除还是停用。

### 简单统计与设置

统计只做同一月份的收入 / 支出分类排行，用横向进度条、金额与占比表达，不引入图表框架。分类合计应与明细完全一致，停用分类产生的历史记录也计入统计。

设置页先放分类管理、备份导出、版本信息和“数据保存在本机”的说明。备份用系统文件选择器保存；API 设置待 v0.3 接入时加入。

### 视觉方向

推荐“卡片明细”：雾白背景、蓝色强调色、柔和的大圆角、清楚的金额和简单分类图标，沿用咔皮公开展示的信息分区方式。

另提供“账单优先”方案：月度概览更紧凑，把更多屏幕空间交给记录列表，适合经常核对明细。

两种方案功能相同，区别在首页层次。支持系统深色模式。正文使用系统字体，分类图标使用稳定的矢量图标，收入 / 支出同时用文字和符号区分。首版不用角色动画；插画可以在空状态和保存反馈中逐步加入。

## 4. 分类管理规则

这部分比图标本身更重要，避免分类改动影响账目。

| 操作 | 规则 |
| --- | --- |
| 新增 | 填名称，选图标与颜色；收入和支出分别管理，同类型名称不可重复 |
| 预设分类 | 除兜底分类外，拥有与自建分类相同的编辑能力 |
| 改名 / 换图标 | 历史记录仍属于同一个分类，展示同步更新，金额不变 |
| 调整顺序 | 管理页与记账网格使用相同顺序 |
| 停用 | 新记账时不再显示，历史明细和统计保留；允许恢复 |
| 删除未使用分类 | 确认后删除分类，不涉及记录 |
| 删除已使用分类 | 不删除账目，提示停用；跨分类合并后续再做 |
| 兜底分类 | 收入、支出各保留一个，不可停用或删除；允许调整展示名称和图标 |
| 已停用分类的旧记录 | 可以保留原分类继续修改金额 / 备注，也可以手动换成其他有效分类 |

默认支出分类建议：餐饮、交通、购物、居住、娱乐、医疗、学习、其他支出。默认收入分类建议：工资、奖金、兼职、红包、其他收入。均可按个人习惯调整。

第一版使用一级分类。后续若需要“餐饮 → 早餐 / 午餐 / 咖啡”等二级分类，通过明确的 Room 迁移扩展；本版不先增加空的二级分类界面。

记录删除需要明确确认，并保留可撤销的软删除状态。关闭或切换页面时，未保存草稿要保留或提醒处理。

## 5. 为后续 AI 记账留好的流程

v0.3 第一轮只做文字输入，例如“午饭 25 元，地铁 6 元”。SiliconFlow Qwen3.5-4B 关闭深度思考，返回一笔或多笔可编辑草稿。

流程为：输入文字 → AI 解析 → 显示金额、类型、日期、分类 → 用户修改 / 确认 → 保存到同一个 Room 数据库。

AI 分类使用当前启用的自定义分类；不凭名称猜出一个不存在的分类。无法匹配时回落到对应兜底分类，并让用户修改。AI 不直接新增分类、不直接删除或修改既有账目。

请求失败保留原文，允许重试或转为手动录入。不会把“没收到结果”当成“已记好”。第一轮不让模型自动提交账目。

API Key 在设备端输入、用 Android Keystore 保护本机保存，不进入源码、BuildConfig、APK 静态配置、日志或账目备份。解析请求仅携带用户这次输入和分类信息，不默认上传整本历史账目。

## 6. 实现边界

保持 Kotlin、Compose + Material 3、Room、ViewModel + Coroutines + Flow，继续使用当前命令行构建入口。Room 及其编译插件版本在实施时核对；Retrofit / OkHttp 在接入 AI 时再增加。无需 Android Studio、依赖注入框架或图表框架。

目录按实际功能逐步增加：

```text
ui/
  home/          明细与月度概览
  entry/         新增和编辑记录
  category/      分类管理
  statistics/    分类排行
  settings/      分类入口和备份导出
  theme/         颜色、字体和公共视觉
data/
  local/         Room Entity、DAO、数据库与迁移
  repository/    记录、分类和备份操作
```

分类有稳定 ID、类型、名称、图标标识、颜色、排序和停用状态。记录保存分类 ID、收支类型、以“分”为单位的 Long 金额、账目日期、备注、创建 / 修改时间和软删除状态。明细、汇总和统计从同一份数据产生。

不使用浮点数存钱；分类改名不靠替换每笔记录的名称；数据库升级不使用会清空账目的破坏性迁移。备份包含版本号、分类和记录；导入恢复放到后续小版，实施前增加内容校验和预览。

## 7. 开发与验收顺序

1. Room + 分类基础：初始化默认分类，验证新增、改名、停用与恢复；构建并检查迁移与关联约束。
2. 手动记录：新增、编辑、删除与撤销，金额验证，草稿保留；重新构建，验证重启 App 后数据仍存在。
3. 首页与分类管理：实现概览、日期分组、图标网格和排序；重新构建并检查大小字体、键盘遮挡与返回行为。
4. 简单统计与备份：对照明细核验汇总，导出完整备份；构建、lint、签名检查，并在手机上验收。

必须通过的用户场景：

- 记一笔餐饮支出 25 元，首页、当天汇总、本月汇总和分类统计一致。
- 添加自定义分类“咖啡”，用它记账；改名后旧记录正确展示新名称。
- 停用已使用分类后，原记录与统计仍保留，新记账网格不再出现它；恢复后可继续使用。
- 删除有账目的分类不会删掉账目；删除空分类不会破坏其他分类。
- 编辑记录的金额、日期或收支类型后，相应月份与分类统计同步变化。
- 关闭并重开 App，记录、分类及顺序仍保留；连续点保存不会产生重复记录。
- 没有记录时显示真实空状态；设备断网时本版全部记账功能仍可使用。
- 键盘打开、大字体、长备注和较多分类时，保存按钮与关键操作仍可触达。
- 备份中记录数、分类数与本机一致，不包含 API Key。

设计提案阶段仅交付文档与页面预览。用户确认后已开始并完成 v0.2 功能代码，实际验证单独记录。

页面预览已检查：金额小数位校验、新增记录后汇总更新、分类改名同步旧记录、已使用分类删除时提示停用、停用后历史统计保留且录入网格隐藏、两种布局切换、320px 窄屏无横向溢出。这些检查只验证设计预览，不代表 Android 功能已经实现或经过真机测试。
