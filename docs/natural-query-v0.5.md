# v0.5 一句话查账与 AI 复核

## 使用方式

从首页右上角“搜索账目”进入，再点“用一句话查账”。输入明确时间和目标，例如“这个月坐地铁花了多少？”或“上个月最大的一笔支出是什么？”。使用与文字记账相同的硅基流动 Key 和 `Qwen/Qwen3.5-4B`，关闭深度思考。

先理解问题，再本地筛选、计算并显示结果，同时自动复核。页面列出日期、收支类型、分类、关键词与金额边界，以及全部命中明细；最大单笔或前 N 笔会标记所选答案，较小的候选记录仍保留显示。点击记录可以编辑，返回后重算并提示重新复核。

例如“地铁去公司 6 元”和“地铁站旁买早餐 18 元”都能被关键词“地铁”命中。本地先显示 24 元，AI 应指出早餐并非乘车费用。用户确认“仅从本次统计排除”后变为 6 元，两笔原始账目均保留，也可重新纳入。该操作影响当前结果，不删除或自动修改分类。

## 边界和隐私

- 查询支持合计、笔数、最大单笔、前 1–20 笔、明细；每次最多 500 字。
- 自然月包含完整月份，本周从周一到周日，最近 N 天包含今天，自定义日期包含起止日。没有明确时间范围时要求补充；明确“所有历史”才查询全账本。
- 日期、分类、收支、金额条件相互取交集，多个备注关键词取任意一个命中。已删除账目不统计，停用分类的历史账目仍可查询。
- 不支持比较、趋势、建议、余额、转账、借还款、退款、修改指令或多轮指代。含糊和非法条件报错，不降级为更宽的查询。
- 理解请求发送问题、当天日期和分类。复核另外发送当前命中记录的日期、金额、分类、备注和当前统计状态，不发送其他历史记录或 Key 给模型内容。
- 每批最多 20 笔，全部批次完成才显示完成。失败或取消保留结果及已检查进度；零条结果也复核查询范围。编辑、恢复或排除调整后，旧复核失效，需用户重新触发。
- AI 只标疑问，不自动排除记录，也不替代本机合计。关键词可能漏掉未写明用途的账目，复核不保证原账本完整或没有遗漏。
- 沿用 Room schema 2，无数据库迁移；正式账本不注入测试数据。

## 验证方式

普通回归：`scripts/test-emulator.ps1`。包含本地日期和统计规则、非法响应、模拟网络、UI 分批复核失败与取消、排除重算、编辑返回、深色主题和大字体、原生键盘遮挡检查。付费测试默认跳过。

真实模型：`scripts/test-ai-local.ps1 -AllowPaidRequests`，Key 单独一行保存在 `.tools/secrets/siliconflow-api-key.txt`。电脑直接运行同一生产 Kotlin 网络与校验代码，使用合成账目，五次请求，不需要手机安装。手机端也保留 `scripts/test-ai-phone.ps1 -AllowPaidRequests -Inquiry`；华为系统安装提示仍需用户确认。

本版首轮手机真实测试识别出了“地铁站旁早餐”的语义误命中，也发现模型把最大支出查询中的较小候选误判为无关。已给复核数据增加本机所选答案标记，并明确候选池和最终答案的区别；修正后的真实模型验收以电脑端显式付费测试结果为准。

## 2026-10-15 验证结果

- Debug APK、Android 测试 APK 构建通过；lint 为 0 错误、15 条现存警告。
- JVM 常规单元测试 19 项通过，真实接口测试默认跳过。
- API 31 模拟器 24 项常规设备测试通过，2 项真实接口测试按默认策略跳过；已检查查账疑问明细、深色大字体和原生键盘截图。
- 电脑端真实接口验收通过，共 5 次请求，约 11.4 秒。地铁查询正确展开当前自然月并得到两条候选；复核指出早餐语义不符，确认排除后的本地金额由 24 元变为 6 元，原数据保留。
- 上个月最大支出正确选中 2000 元房租，15 元打车仍是有效候选，复核未再误报；文字记账保留“小巷早餐店、豆浆油条、公交去医院”。
- 真实验收使用固定合成数据，没有读取、修改正式账本，也没有在电脑端测试期间安装手机 App。真实模型具有波动性，这些用例通过不代表任意问题都能正确理解。

手机此前安装的是早期 v0.5 测试构建；本次复核修正已包含在最终 Debug APK 中，未再次触发手机系统安装确认。电脑测试不覆盖华为设备特有的所有行为。
